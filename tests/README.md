# 测试目录

与 `scripts/` 的分工：**scripts 放运维与诊断工具，tests 放可重复执行的测试**。
测试的目标是「改完代码后能一键确认没有把好东西改坏」，因此全部不需要启动服务、
不需要占用主数据库，单条命令即可运行全部。

```bat
scripts\run_tests.bat        :: 一键跑全部三项
```

| 测试 | 验证什么 | 什么时候会抓到问题 |
|---|---|---|
| `test_report.py` | 报告生成回归：字段、结构、空值兜底 | 改了评分/报告字段后 |
| `smoke_test.py` | 全部 API 端点 + **并发阶段** | 改了 API/展示层后 |
| `test_serving_concurrency.py` | 展示层读取器在多线程下的行为 | 专测懒加载视图的竞态 |

## 为什么冒烟测试必须有「并发阶段」

真实故障复盘：`ServingReader` 早期是「单连接 + 跨线程共享的视图集合」，
串行请求时 15 个接口全部 200，**看起来完全正常**；但浏览器一次刷新会并发打多个接口，
两个线程同时懒加载视图就产生竞态，报 `Table with name xxx does not exist`。
**教训：只测串行的测试会给出虚假的绿灯**，所以并发阶段是必测项而非可选项。

## 各测试说明

### smoke_test.py

两个阶段：

1. **串行**：逐个请求全部端点，验证功能正确；
2. **并发**：用线程池同时打 10 个端点 × 3 轮，验证线程安全。

### test_serving_concurrency.py

更聚焦的并发回归：用「起跑线事件」让多个线程**同时**触发懒加载视图，
精确复现历史上的竞态场景（第一轮最容易崩）。

### test_report.py

构造最小输入直接调用报告生成器，校验产物结构——
不依赖数据库快照的新鲜度，适合在改字段名/评分口径后快速确认。

## 新增测试的约定

- 文件名以 `test_` 开头，能被 `run_tests.bat` 一次性纳入；
- **不得**依赖主库写锁（需要写库的测试先想清楚是否真的必要）；
- 涉及网络/外部数据的测试必须有明确的失败提示与降级路径。
